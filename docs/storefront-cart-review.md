`/cart` is a small Server Component entry to existing browser/session reads. A readable heading and count lead into restrained seller groups with actual store links, square thumbnails, complete product/option evidence, exact prices, availability and native quantity/remove controls. Plain rows/dividers replace repeated floating cards. Desktop adds one tan summary beside the groups; mobile stacks complete rows and the summary rather than squeezing a desktop table. A cart-local boundary Tab handler cycles the first/last visible controls; Chromium otherwise temporarily hands focus to browser chrome/body. It does not replace native dialog authority or change operational/navigation dialogs.

## Architecture and truthful commerce

- Cart responses are validated before entering shared state: UUID identity and deduplication, seller/items, currency, nonnegative bounded decimal strings, safe integer counts/stock, same-product relative public image streams and consistent server counts/amounts. BigInt only checks supplied amounts; it never creates a charge or converts money to floats. More than 1,000 lines/groups fails visibly rather than silently dropping purchasable evidence. Backend cart pagination remains separate debt.
- The root SessionCartProvider derives a presentation identity from existing auth state. Tagged cart/overlay results hide previous account evidence immediately without remounting unrelated page content. Obsolete reads are aborted/discarded; accepted mutations invalidate older reads. Shared mutation serialization prevents overlapping updates, and account/unmount changes reject late completion. Cookies and Django cart ownership remain authority. An already dispatched request is not represented as cancelled on the server; broader coordination of session changes and in-flight unsafe transport remains separate.
- Load failures and malformed successful responses are explicit retryable errors, not empty carts. Only a validated empty response produces the shopping recovery. Unknown load counts remain unknown in the existing header. Mutation failures retain confirmed quantities and focused errors. No optimistic amount or success timer is introduced; update/remove/clear confirmation waits for acceptance. Malformed mutation responses invalidate uncertain cart evidence. Local feedback blocks checkout after rejection until correction/reload; stock and pending states also render a genuinely disabled button with no checkout link.
- Quantity cannot go below one through decrement; removal remains explicit. Increase follows the supplied stock bound, while Django revalidates unsafe updates and checkout. Controls freeze during pending operations and retain real API errors/retry. All unsafe requests use the unchanged same-origin API client, fresh CSRF and redirect rejection. No credential storage, backend, schema, authentication, tenant or payment changes are introduced.
- Every amount displays its original decimal string and supplied currency with Money. Cart API evidence supplies subtotal only: shipping, taxes and final discounts remain “calculated/determined at checkout.” Items total repeats the actual subtotal, not a fabricated grand total. Unconditional free shipping, encryption/seller guarantees, verification and thousands-of-products claims are removed.
- Promo validation is an explicit eligibility preview using the existing endpoint. Its server-supplied discount is validated/displayed without subtracting it from cart totals or claiming persisted application/redemption. Code, preview and delayed results reset with every accepted cart revision/account change. Checkout determines actual discounts; this UI creates no new coupon transfer workflow.
- Public image URLs remain same-origin Django streams, accepting the backend cart's existing optional trailing slash. The installed Next Image component uses native lazy loading and its per-image `unoptimized` option to preserve the existing direct stream, square containment and cached/loading/error/missing states. Broken images use an accessible icon instead of exposing a browser failure glyph or clipped text. No optimizer/storage bypass, invented merchandise asset or image dependency is introduced.
