## Implementation and contracts

Search and category pages share a feature-oriented discovery layout behind small public Server Component/Suspense entries. The concise local serif heading, actual count, simple toolbar and active filters replace the old boxed filter layouts. Desktop has a 14rem filter rail from 1,024px; mobile/tablet has a native filter drawer. Product grids use two columns on mobile, three from 640px and four from 1,280px within 80rem. Square image geometry, readable names, actual seller, optional brand/rating, exact currency/price and real stock take precedence over badges and card chrome. Other route compositions and shared seller/PDP cards remain intact.

Both routes use the existing faceted search API, with fixed 20-result pages. URL parameters own query, category/brand identity or slug, seller, exact decimal bounds, availability, rating, sort and page. Changing filters/sort resets to page one, while Previous/Next and browser history preserve applied state. Category identity stays in the route even when filters are cleared. UUID case is canonicalized; selected slugs receive the same visible/semantic state as UUID filters. Unsupported, repeated or invalid parameters fail visibly before requesting products. Pagination destinations are reconstructed from local allowlisted state, never copied from response URLs.

Price inputs compare bounded decimal strings with BigInt, retaining large exact digits. Search filters apply each product's listed units; no currency conversion exists. Therefore range labels omit the backend's hard-coded dollar signs. Price-bracket counts are omitted because their half-open maximum disagrees with the backend's inclusive applied maximum. Other facet counts explicitly describe the text-query population before filters. Product prices retain their actual ISO currency and exact financial formatter.

Independent cancelable reads validate consumed products, categories and facets. Shared evidence helpers preserve the homepage's validation while covering discovery IDs, exact money/currency, rating/count/stock and same-product relative public media URLs. Categories are bounded to 1,000 metadata records because the existing API is unpaginated; excess data is an explicit failure. URL changes immediately discard old products, facets and counts. Late aborted success/failure cannot overwrite newer state, including Strict Mode and unmounts. Errors/malformed responses never become successful empty data. Category metadata can fail/retry independently of products.

Drawer edits stay in memory until Apply; Close/Escape discard them. Clear resets the draft and preserves route category/sort. Native focus containment, scroll locking and opener return use existing primitives; desktop resizing closes the drawer and focuses the visible result heading. The filter list scrolls independently of the fixed action area. Genuine empty results offer reset, a real category suggestion and another search. Empty later pages retain filters when returning to page one. Existing real autocomplete remains unchanged. Django/API/session/CSRF/tenant/inventory/financial authority, dependencies and browser credential-storage rules are preserved.
