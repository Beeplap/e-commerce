## Architecture and truthful commerce

- Validate the requested UUID and consumed response identity, category, seller, currency, exact prices, stock consistency, option attributes, images and review evidence before exposing purchase controls. Malformed successful responses stay errors; 404 recovery stays distinct from temporary failure. Retry clears old evidence. Product/user keys and AbortController checks discard obsolete reads and local purchase completion, including Strict Mode cleanup and unmount.
- Presentation bounds are ten active images (the existing backend limit), 1,000 options with up to 100 attributes each, and ten recent reviews. Larger or contradictory evidence fails visibly; never truncate purchasable options silently. These bounds do not repair backend unpaginated option/review aggregation and are not authorization.
- Gallery URLs must be relative Django public streams for the same product/image UUID. No external/storage URLs or optimizer authority bypass is added. Eager main images use stable square contain geometry; lazy thumbnails use native pressed-state buttons. Loading, cached success, broken images and absent photographs are explicit. No zoom dependency or invented merchandise imagery is introduced.
- Select an available option first when one exists. Exact option prices, selected state and dashed/out-of-stock labels distinguish choices. Unavailable options remain inspectable while purchase disables. Option changes reset quantity to one. A single option needs no redundant selectable SKU card; actual attributes/SKU remain in specifications.
- Stock/quantity bounds describe received evidence, not reservations. Send only selected variant UUID and integer quantity through the unchanged provider, API client and fresh-CSRF path. A synchronous guard blocks duplicate submissions. Choices stay fixed while pending. Confirm success only after acceptance, preserve provider cart opening, show/focus rejection and allow retry. Product/user/unmount changes discard local completion; broader shared-provider races remain separate work.
- Preserve original decimal strings/currency with exact Money/BigInt formatting. Compare prior prices with BigInt and show them only if strictly higher. Never calculate prices/totals in floats. The UI displays the currency supplied by the backend, including its inherited currency-policy limitations.
- Actual seller UUID/name evidence supports store links, not verification or shipping badges. Only a review with `verified_purchase=true` receives that label. Dates use `en-US` and UTC; descriptions remain plain React text. Semantic rating meters display actual counts. Delivery copy states that options/charges appear at checkout and that this listing provides no date. No speed, free-shipping, returns, reservation or Buy Now promise is invented.
- Related products are a validated first-page category preview: at most 25 received records, four shown, current product excluded. This is not a recommendation/ranking service. Never follow response pagination URLs. Error/retry and genuine empty results stay local to that section. Brand discovery uses the existing `/search?brand=<UUID>` route, replacing an unsupported brand route.
