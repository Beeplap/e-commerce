# Customer shell review — Phase 36

Phase 36 implements only header, navigation, autocomplete, mobile navigation and footer. Work is isolated on `ui-overhaul-phase36-shell`, based on validated foundation `cb0bd0a` and committed functional integration `803970d`. The original worktree's concurrent backend/account/proxy/product/seller changes are preserved and excluded from this branch's acceptance claims. No backend, API/auth/CSRF/tenant, cart provider, payment handler, dependency or business workflow changed. STOP here; Phase 37 requires an explicit request.

## Design and real destinations

The cream header uses compact editorial branding and restrained outline actions. Shop/category/seller/new-arrival navigation is visible on desktop; search occupies at most 256px rather than swallowing the navigation. Mobile has a compact brand/action row and full-width search. Tablet uses a compact inline field and the navigation drawer. The announcement says “Independent sellers. One marketplace.” without fabricated verification or delivery promises. Loaded cart counts are real; an unavailable count is a dash with a readable accessible description.

Categories come from the existing public category API. Sellers is a labeled preview of up to eight distinct stores from the first 25 newest catalog products, not a complete directory or ranking. Actual seller/category URLs are encoded. Both discovery areas preserve visible loading/error/retry/empty distinctions. Current locations have color and an underline. The espresso footer separates a short editorial introduction, three actual shop/account/seller link groups, and compact branding/copyright. Absent policies/help/company/social pages are omitted rather than filled with dead links or invented features.

Autocomplete retains the real debounced API and precise decimal/currency display. Suggestions, categories, brands and products all participate in keyboard selection with unique IDs and an active descendant. Aborted/stale responses cannot overwrite a new query or reopen a dismissed field. Escape clears selection; Enter then searches the typed query. “View all results” always searches the full query. Failed suggestions remain explicit while full search stays available. Response validation respects Django's existing query sanitization/cap without weakening generation guards.

The native mobile drawer uses the existing customer overlay's modality, focus loops and scroll cleanup. First Escape dismisses autocomplete; the next closes navigation before the native search input can consume it. Closing restores the opener. Resizing into desktop navigation closes the drawer and focuses the visible brand. A skip link reaches the focusable main landmark on the nine existing customer route patterns; route content/workflows are unchanged.
